# Sponsorship proposal (owner action required)

**Status:** draft only — do **not** commit `.github/FUNDING.yml` until a verified sponsorship
account is confirmed. Enabling funding links without a working account is misleading.

## Goal

Optional maintainer support for ongoing open-source maintenance of Aether UI (registry, CLI, MCP,
docs, and component quality), without gating Core MIT usage behind a paywall.

## Recommended first step

1. Create / verify a [GitHub Sponsors](https://github.com/sponsors) profile for the repository owner
   (individual or organization).
2. Confirm the public Sponsors page accepts payments in the intended regions.
3. Only then add `.github/FUNDING.yml`, for example:

```yaml
# Example — do not enable until the account is live
github: bogdanmartinescu
```

4. Optionally link the same Sponsors URL from the docs site footer and README once live.

## What sponsorship should and should not imply

Should:

- Thank-you acknowledgements
- Prioritized triage of community issues when capacity allows
- Transparency notes in release posts when relevant

Should not:

- Promise SLA / guaranteed response times without a paid support product
- Restrict MIT Core usage or registry installs
- Substitute for a future Pro/commercial offering (M4) — keep those separate

## Alternatives considered

| Option | Notes |
| --- | --- |
| GitHub Sponsors | Lowest friction for GitHub-hosted projects |
| Open Collective | Better for multi-maintainer expense transparency; more setup |
| None for now | Acceptable until traffic and support load justify it |

## Decision

Owner decides whether and when to enable Sponsors. Until then, public copy must not claim that
sponsorship is available.
