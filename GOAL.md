# Aether UI — continuous development goal

Develop Aether UI into an open-code, AI-native application design system that helps humans and coding agents build, validate and maintain production-quality React applications. The intended differentiator is reliable feature composition, source ownership, safe upgrades and design-system validation, not component count.

## Mission constraints
Public Core, public registry, native CLI, local MCP, public recipes and local diagnostics are intended to remain MIT and free for commercial use. Verify ownership/license provenance before changing legal files; never relicense existing contributions or hide essential maintenance behind payment. Paid kits, optional hosted infrastructure and sponsorships are distinct; commercial launch and spending require owner approval.

## Execution
Follow AGENTS.md. Start at M0 and select the earliest dependency-ready task. Implement actual working features, not placeholders or marketing claims. Reconcile code, registry, exports, examples and docs. Run applicable checks, record exact commands/results, update task state, commit narrowly and continue to the next unblocked task until the active milestone meets its exit gate. Reconcile state against the actual tree on each new session.

Continue across approved public engineering milestones without asking about routine implementation choices. Stop at a genuine security/legal/product blocker, explicit approval gate, exhausted execution budget, or when all approved milestones are complete. Record the next action and resume from that checkpoint on the next invocation. No unbounded unattended execution, auto-publishing, purchases, or fabricated test outcomes.

Completion of a feature means its acceptance criteria and Definition of Done pass. Completion of the platform means all approved milestone gates pass; gated Pro/Cloud work remains pending owner authorization and evidence, not falsely complete. Thereafter transition to maintenance, feedback-driven iteration and documented quarterly planning.
